# 결정 0001 — 저장소 내부 OKF 도입

상태: 채택 · 날짜: 2026-09-17 · 근거: 외부 링크 없이 저장소 내부에 지식 구조를 정의하려는 사용자 요청

## 문제

현재 설명, 구현 계획, 당시의 완료 보고가 여러 폴더에 섞여 있다. 전략 후보 목록의 체크박스가 구현 여부로 오해될 수 있고, DB 문서에는 현재 수집 코드와 다른 쓰기 정책이 남아 있다. 새 작업이 과거 미완료 목록을 다시 실행할 위험이 있다.

## 선택

- [OKF 규약](../../OKF.md)을 프로젝트 내부 정의로 채택한다.
- 지식 홈 → 문서 등록부 → 개념/담당 문서 → 코드·검증 근거로 탐색한다.
- 문서 종류와 최신성 상태를 분리하고, 과거 기록을 현재 지시와 구분한다.
- 현재 문서 경로는 유지한다. 코드·테스트와 기존 링크를 깨지 않는 논리 분류를 먼저 적용한다.
- 등록부를 문서 분류의 기준으로 삼고 각 문서에 같은 메타데이터를 중복 관리하지 않는다.

## 다른 선택과 비용

폴더 전체 이동은 외부 북마크와 테스트 참조를 바꾸며, DB 설계안의 내용까지 최신화하는 것은 별도의 코드 대조 작업이 필요하다. 이번에는 등록부에서 차이를 표시한다. 별도 위키 서비스나 그래프 DB는 작은 저장소의 유지 비용에 비해 필요성이 확인되지 않았다.

## 결과와 제약

문서 역할과 읽는 순서는 명확해지지만 과거 문서의 모든 내용이 자동으로 최신화되지는 않는다. `review-required` 항목은 후속 문서 정합성 작업에서 개별 검토한다. 이번 결정은 제품 정책, 주문 권한, 작업 승인 절차를 바꾸지 않는다.
