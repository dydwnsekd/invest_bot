# 대시보드 잔여 작업 실행 계획

> 상태: 6단계 완료 · 다음 작업: 7단계 대시보드 설정 저장 고도화
> 기준일: 2026-09-08
> 운영 방식: 아래 항목을 **한 번에 하나씩** 구현하고, 해당 항목의 검증을 통과한 뒤 다음 항목으로 진행한다.

## 목표와 범위

이 계획은 사용자가 여러 종목과 전략을 비교하고, 백테스트 결과의 근거와 한계를 이해할 수 있도록 대시보드를 단계적으로 개선하기 위한 실행 기준이다.

- 홈과 관심종목 화면은 조회 중심으로 유지하며, 화면 진입만으로 데이터 수집·분석을 실행하지 않는다.
- 매수·매도 신호는 투자 판단 보조 정보로 표시한다. 실제 주문, 자동 매매, 투자 조언 기능은 범위에 포함하지 않는다.
- 기존 Streamlit, Plotly, Pandas 및 현재 데이터 산출물 구조를 우선 활용한다. 새 의존성이나 DB 스키마는 이 계획의 기본 범위에 포함하지 않는다.
- 각 단계는 독립된 변경 단위와 커밋 단위로 관리한다.

## 이미 반영되어 재구현하지 않는 항목

홈 화면에는 시장 기준일, 마지막 수집 시각, 최신 분석 산출물 시각이 분리되어 표시된다. 관심종목에는 종목별 수집 저장 시각과 분석 생성 시각, 갱신 필요 여부 및 갱신 화면 이동 동선이 구현되어 있다.

따라서 기존 작업 목록의 `최신 수집/분석 시각 강조`는 코드 구현 항목이 아니라 문서 상태를 정리하는 항목으로 취급한다. 이후 단계에서 리포트·데이터 탐색 화면에도 같은 맥락의 시간이 필요하다는 근거가 확인될 때에만 해당 화면에 한정해 보완한다.

## 공통 완료·검증 게이트

모든 단계는 아래 조건을 만족해야 완료로 본다.

1. 기능 완료 기준과 예외 처리 문구를 코드와 화면에서 확인한다.
2. 변경한 동작을 검증하는 단위/회귀 테스트를 추가하거나 기존 테스트를 갱신한다.
3. 대상 테스트 후 전체 테스트를 실행한다.

   ```bash
   PYTHONPATH=. .venv/bin/pytest tests/test_streamlit_dashboard.py -q
   PYTHONPATH=. .venv/bin/pytest -q
   git diff --check
   ```

4. UI 변경이면 로컬 웹 화면에서 다음을 확인한다.

   - 정상 데이터, 데이터가 없는 경우, 일부 데이터가 누락된 경우를 각각 확인한다.
   - 버튼·필터·선택 컨트롤이 의도하지 않은 수집/분석 작업을 실행하지 않는지 확인한다.
   - 데스크톱 폭에서 제목, 수치, 범례, 안내 문구가 겹치거나 잘리지 않는지 확인한다.
   - 투자 판단에 영향을 주는 기준일, 데이터 범위, 비용 미반영 등 한계가 화면에 보이는지 확인한다.

5. 검증 결과와 남은 한계를 작업 문서에 반영하고, 한 단계만 포함한 커밋 메시지를 작성한다.

테스트 실패나 화면 회귀가 있으면 다음 단계로 넘어가지 않고 해당 단계를 보완한다.

### [x] 1. 종목 비교 차트 MVP

**목적**

한 종목의 리포트만 보는 흐름에서 벗어나, 사용자가 관심 종목 2~3개의 가격 흐름과 성과 차이를 같은 기간 기준으로 비교할 수 있게 한다.

**구현 방향**

- `데이터 보기` 흐름 안에 별도 내비게이션을 추가하지 않는 종목 비교 영역을 둔다.
- 비교할 종목, 공통 기간, 표시 기준을 사용자가 명시적으로 선택한다.
- 기본 표시는 시작일을 100으로 환산한 누적 흐름으로 하여 가격대가 다른 종목도 비교할 수 있게 한다.
- 원가격 보기와 기준값 100 보기는 혼동되지 않도록 선택 상태와 축/범례에 명확히 표시한다.
- 종목별 거래일이 다르거나 데이터가 부족하면 비교 불가 사유와 실제 사용 기간을 안내한다.

**완료 기준**

- 2~3개 종목을 같은 기간에 비교할 수 있다.
- 기준값 100과 원가격의 의미, 데이터 기준일, 누락 데이터 처리가 화면에서 명확하다.
- 조회 기능만 수행하며 원천 데이터·분석 결과를 변경하거나 수집 작업을 실행하지 않는다.

**검증 방법**

- 날짜 정렬, 공통 기간 산출, 기준값 100 환산을 작은 입력 데이터로 단위 테스트한다.
- 한 종목만 선택, 종목 데이터 없음, 기간 중 일부 누락, 정상 다종목을 회귀 테스트한다.
- 로컬 화면에서 범례·축·기간 안내와 반응형 배치를 확인한다.

**예상 변경 지점**

- `streamlit_data.py`
- `streamlit_charts.py`
- `tests/test_streamlit_dashboard.py` 및 필요한 백테스트/차트 테스트

**검증 기록 (2026-08-30)**

- `데이터 보기` 상단에 저장된 일봉 데이터만 사용하는 2~3종목 비교 영역을 추가했다.
- 공통 거래일만 정렬하고 선택 기간의 첫 공통 거래일을 100으로 환산하며, 종가·날짜가 부족한 종목과 공통 거래일이 없는 경우를 안내한다.
- 대시보드 관련 테스트 127건 및 전체 테스트 292건을 통과했고, 로컬 화면에서 2개 종목·3개월·기준값 100 비교 차트가 정상 렌더링됨을 확인했다.

### [x] 2. 백테스트 일별 평가금액(mark-to-market) 곡선

**목적**

체결 순서만 잇는 누적 수익률과 별도로, 보유 기간 중 손익 변동을 일별로 확인할 수 있게 한다.

**구현 방향**

- 초기 자본을 명시하고, 보유 중인 포지션을 매 거래일 종가로 평가한 자산 곡선을 계산한다.
- 기존 체결 기준 누적 수익률은 제거하지 않고, 두 지표의 계산 기준 차이를 설명한다.
- 수수료·세금·슬리피지가 반영되지 않는 경우 이를 차트 근처에 명시한다.

**완료 기준**

- 진입·보유·청산·마지막 날 강제 청산의 평가금액이 거래일 단위로 일관되게 계산된다.
- 결과 화면에서 체결 기준 성과와 일별 평가금액 곡선을 구분해 볼 수 있다.
- 계산에 쓰인 기간, 종목, 전략 및 비용 가정이 결과와 함께 확인된다.

**검증 방법**

- 평탄한 가격, 매수 후 보유, 중도 청산, 마지막 날 청산의 합성 시계열 테스트를 작성한다.
- 일별 곡선의 날짜 순서, 시작값, 최종값이 거래 로그 및 요약 수익률과 논리적으로 일치하는지 확인한다.
- 기존 백테스트 결과 카드·거래 로그가 깨지지 않는지 회귀 테스트와 화면 확인을 수행한다.

**예상 변경 지점**

- `backtest/`의 성과 계산 로직
- `streamlit_backtest.py`
- 관련 테스트 파일

**검증 기록 (2026-09-02)**

- 신호 다음 거래일 종가 체결 규칙과 기존 거래 로그를 이용해, 가상 초기자금 1,000,000원을 보유 기간의 매 거래일 종가로 평가하는 곡선을 추가했다.
- 거래 순서 누적 수익률과 일별 평가금액을 분리해 표시하고, 평가 기간·종목/전략·수수료·세금·슬리피지 미반영 가정을 결과에 고정 표시한다.
- 백테스트 관련 테스트 19건과 전체 테스트 293건을 통과했고, 로컬 백테스트 화면에서 곡선·가정 문구가 정상 렌더링됨과 브라우저 오류 로그가 없음을 확인했다.

### [x] 3. 백테스트 실행 이력 조회·재불러오기

**목적**

현재 세션에서만 보이는 백테스트 결과를 기존 산출물 기준으로 다시 선택해 비교할 수 있게 한다.

**구현 방향**

- 기존 `run_group_id`, `run_id`, 종목·전략·데이터 기준일·생성 시각 등 저장된 메타데이터를 사용한다.
- 이력 선택은 결과를 읽기만 하며, 선택 자체로 백테스트를 다시 실행하지 않는다.
- 산출물 일부가 없거나 원천 데이터와 기준이 다르면 재현 가능 여부와 제한을 안내한다.

**완료 기준**

- 실행 이력 목록에서 실행 시각, 대상 종목, 전략, 데이터 기간/기준일을 확인하고 선택할 수 있다.
- 선택한 이력의 요약, 거래 로그, 일별 평가금액(2단계 완료 후)이 현재 실행 결과와 같은 방식으로 표시된다.
- 누락·손상·호환되지 않는 이력은 앱 오류 대신 이해 가능한 안내를 제공한다.

**검증 방법**

- 임시 저장소에서 이력 목록 정렬·필터·단건 재불러오기를 테스트한다.
- 저장한 결과와 다시 불러온 결과의 핵심 수치·거래 행·날짜 범위가 같은지 비교한다.
- 이력 선택 경로에서 백테스트 실행 함수가 호출되지 않는지 모킹으로 검증한다.

**예상 변경 지점**

- `backtest/persistence.py`
- `streamlit_backtest.py`
- 관련 테스트 파일

**검증 기록 (2026-09-04)**

- 저장된 `backtest_summaries`와 `backtest_trades` artifact를 실행 시각 내림차순으로 조회하고, 종목·전략 필터와 실행 시각·종목·전략·신호 원본을 먼저 보여주는 선택 UI를 추가했다.
- 선택한 이력은 저장된 요약·거래 로그를 읽어 현재 실행 결과와 같은 카드·비교표·누적 수익률·일별 평가금액 화면으로 복원한다. 신호 원본이 없거나 거래 로그가 누락된 경우에는 영향을 설명하고 해당 영역만 비워 둔다.
- 이력 선택 경로가 백테스트 실행 함수를 호출하지 않는지 모킹으로 확인했고, 파일 저장소의 전체 이력 정렬·단건 로드 및 저장/재불러오기 결과의 핵심 수치·거래일 범위를 회귀 테스트로 검증했다.

### [x] 4. 전략 파라미터 조정 진입 UX

**목적**

전략의 기본값을 무심코 바꾸지 않으면서, 사용자가 어떤 값이 신호와 결과에 영향을 주는지 이해하고 제한된 범위에서 실험할 수 있게 한다.

**구현 방향**

- 전략별로 의미 있는 파라미터만 노출하고, 기본값·허용 범위·변경 효과를 함께 표시한다.
- 초기 상태는 현재 기본 전략과 동일하게 유지한다.
- 실행 전에는 “실험 설정”임을 표시하고, 실행 결과에는 실제 적용값을 남긴다.
- 최적값 추천, 자동 파라미터 탐색, 수익 보장 표현은 포함하지 않는다.

**완료 기준**

- 사용자는 전략별 조절 가능 항목, 기본값, 허용 범위를 알 수 있다.
- 유효하지 않은 범위·조합은 실행 전에 차단하고 수정 방법을 안내한다.
- 결과와 저장 메타데이터에서 실행 당시의 파라미터를 확인할 수 있다.

**검증 방법**

- 기본값 실행 결과가 기존 기준 전략 결과와 동일한지 회귀 테스트한다.
- 범위 밖 값, 역전된 기간, 비어 있는 필수값을 검증하는 테스트를 작성한다.
- 파라미터 변경·초기화·실행·결과 표기의 화면 흐름을 확인한다.

**예상 변경 지점**

- 전략 설정/검증 로직
- `streamlit_backtest.py`
- `backtest/persistence.py`의 기존 메타데이터 활용 범위
- 관련 테스트 파일

**검증 기록 (2026-09-06)**

- 백테스트 실행 조건에 `실험 설정` 영역을 추가했다. Golden Cross의 단기·장기 이동평균 기간, RSI·평균회귀·이격도·모멘텀의 매수/매도 기준만 제한된 범위에서 조절하며, 설정이 없는 전략은 그 사실을 표시한다.
- 초기값은 기존 전략 기본값과 같고, 변경된 설정은 결과 카드·비교표·거래 로그와 `strategy_parameters_json` 저장 메타데이터에 남긴다. Golden Cross의 기본값은 기존 신호 artifact를 계속 사용하며, 기간을 바꾼 실험에만 종가 기반으로 신호를 다시 만든다.
- 범위 밖·비어 있는 값과 단기/장기 기간 역전은 검증해 실행을 막고, 기본값 되돌리기 동선을 제공한다. 기본 RSI 신호 회귀, 사용자 설정 신호 변경, 입력 검증, 초기화, 설정 메타데이터 기록을 테스트했다.

### [x] 5. 복수 전략 조합 방식 설계와 비교 화면

**목적**

여러 전략의 신호가 충돌하거나 일치할 때 어떤 규칙으로 판단했는지 투명하게 보여 주는 기반을 만든다.

**구현 방향**

- 두 전략 이상 선택하면 전략 합의(AND), 하나라도 충족(OR), 가중치 방식을 모두 선택할 수 있게 한다. 기본값은 AND다.
- AND는 모든 전략이 같은 매수 또는 매도일 때만 해당 신호를 내고, 그 외에는 관망한다.
- OR은 매수 또는 매도 신호가 한 전략이라도 있고 반대 신호가 없을 때만 해당 신호를 낸다. 매수·매도 충돌은 관망한다.
- 가중치는 매수에 양수, 매도에 음수를 적용해 합산한다. 점수가 양수면 매수, 음수면 매도, 0이면 관망한다.
- 가중치 입력의 권장 시작값은 전략별 1.0이며, 성과 예측이 아닌 중립 비교 기준으로 설명한다.

**완료 기준**

- 선택 가능한 조합 방식과 각 방식의 신호 생성 규칙을 사용자가 이해할 수 있다.
- 단일 전략 결과와 조합 전략 결과를 같은 기간·같은 비용 가정에서 비교할 수 있다.
- 신호가 없거나 전략별 데이터 조건이 충족되지 않을 때 처리 기준이 명시된다.

**검증 방법**

- 일치, 불일치, 신호 없음, 데이터 부족의 합성 신호 조합 테스트를 작성한다.
- 결과 카드와 거래 로그에 사용한 조합 규칙이 표시되는지 확인한다.
- 저장 이력을 다시 열었을 때도 저장된 조합 규칙을 해석해 표시하는지 확인한다.

**결정 기록 (2026-09-06)**

- AND, OR, 가중치 방식을 모두 제공한다. 기본 선택은 보수적으로 합의가 필요한 AND다.
- 가중치는 선택된 각 전략별로 0.1~3.0 범위에서 입력하며 초기값은 모두 1.0이다. 가중치 합은 1일 필요가 없다.
- OR의 매수·매도 충돌과 가중치 동점(0점)은 모두 관망으로 처리한다.

**검증 기록 (2026-09-06)**

- 복수 전략 선택 시 조합 방식 선택 패널을 추가하고, 개별 전략 결과와 조합 결과를 같은 기간·체결·비용 가정으로 함께 비교하도록 구현했다. 한 전략만 고르면 조합이 적용되지 않는 이유를 화면에 표시한다.
- AND/OR/가중치의 정확한 신호 규칙, 가중치별 점수, 구성 전략별 원본 신호를 조합 결과에 남긴다. 결과 카드·비교표·거래 로그와 `combination_settings_json` 저장 메타데이터에서 적용 규칙을 확인할 수 있으며, 저장 이력도 메타데이터로 규칙을 다시 해석한다.
- 전략 합의·충돌·동점 관망·공통 거래일 부재·잘못된 가중치와, 기본 AND·가중치 입력·결과 저장 메타데이터·이력 규칙 복원을 자동 테스트했다.

### [x] 6. 포트폴리오·다종목 집계 뷰

**목적**

종목별 백테스트 결과를 나란히 보는 수준을 넘어, 동일한 가정으로 묶었을 때의 포트폴리오 흐름과 기여도를 확인하게 한다.

**구현 방향**

- 첫 버전은 조회·비교 목적의 단순한 동일 비중 기준으로 제한한다.
- 종목별 비중, 기간, 결측값 처리, 리밸런싱 가정을 결과 화면에 명시한다.
- 종목별 수익 기여도와 전체 평가금액 곡선을 함께 보여 준다.
- 실제 주문 비중 추천, 자동 리밸런싱, 위험 관리 자동화는 포함하지 않는다.

**완료 기준**

- 여러 종목 결과를 하나의 공통 기간·공통 기준으로 집계할 수 있다.
- 사용자에게 각 종목의 비중, 포함/제외 사유, 전체 성과와 종목별 기여도가 보인다.
- 일부 종목의 거래일 또는 결과가 부족할 때 집계 방식과 제외 이유를 알 수 있다.

**검증 방법**

- 동일 수익률, 상반된 수익률, 결측 종목, 비중 합계 오류의 합성 데이터 테스트를 작성한다.
- 비중 합이 100%인지, 전체 수익률이 각 종목 기여도의 합과 일관되는지 확인한다.
- 로컬 화면에서 종목 수 증가 시 표·차트·안내 문구의 가독성을 확인한다.

**결정 기록 (2026-09-08)**

- 첫 버전은 동일 비중으로 시작 자금을 배분하고, 리밸런싱은 하지 않는다. 실제 주문 비중이나 비중 추천은 제공하지 않는다.
- 선택한 여러 전략은 서로 섞지 않고 전략별로 포트폴리오를 따로 계산하며, 화면에서 확인할 전략을 선택한다.
- 포함 가능한 종목의 공통 거래일만 사용한다. 첫 공통 거래일의 종목별 평가액을 같은 초기자금으로 다시 맞춘 뒤 비교해 데이터 시작일 차이로 인한 기존 손익이 섞이지 않게 한다.
- 일별 평가금액이 2일 미만인 종목은 제외하고, 남은 종목 수가 2개 미만이거나 공통 거래일이 2일 미만이면 해당 전략의 포트폴리오를 계산하지 않고 이유를 표시한다.

**검증 기록 (2026-09-08)**

- 이번 세션에서 두 종목 이상 백테스트했을 때 전략별 동일 비중 포트폴리오 평가금액 곡선, 수익률, 포함·제외 종목 수, 종목별 비중·수익 기여도를 표시한다.
- 결과 화면에 `동일 비중 · 리밸런싱 없음 · 공통 거래일`과 공통 시작일 재기준화 가정을 명시한다. 저장 이력은 현재 단일 실행 결과 복원 범위를 유지하며, 포트폴리오 집계는 이번 세션의 다종목 실행 결과에 한정한다.
- 동일 비중 무리밸런싱 계산, 공통 거래일 재기준화, 수익 기여도 합계, 결측 종목 제외·재가중, 공통 기간 부족, 전략별 분리 집계 및 화면 연결을 자동 테스트했다.

### 7. 대시보드 설정 저장 고도화

**목적**

사용자가 자주 보는 종목, 기간, 필터, 차트 표시 기준을 반복 설정하지 않도록 하되, 현재 사용자 상태와 저장 범위를 투명하게 관리한다.

**구현 방향**

- 우선 저장할 설정을 종목 선택, 기간, 정렬·필터, 차트 표시 방식으로 제한한다.
- 세션 내 유지와 세션을 넘어 유지하는 설정을 구분해 설명한다.
- 기존 저장 구조를 우선 검토하며, 별도 계정·개인정보·신규 DB 스키마가 필요한 방식은 이 단계의 기본 범위에서 제외한다.

**완료 기준**

- 저장 대상과 적용 시점, 초기화 방법을 사용자가 알 수 있다.
- 저장된 설정이 다른 사용자의 화면 상태나 백테스트 실행 결과를 변경하지 않는다.
- 저장 실패 또는 읽기 불가 상태에서 기본값으로 안전하게 복귀한다.

**검증 방법**

- 설정 저장·재실행·초기화의 정상 경로를 테스트한다.
- 손상된 설정, 지원하지 않는 과거 값, 값 누락 시 기본값 복귀를 테스트한다.
- 다른 탭 이동과 새 세션에서 기대한 유지 범위를 화면으로 확인한다.

**구현 전 결정 필요**

- 세션을 넘어 저장할지 여부와 저장 매체
- 사용자별 설정이 필요한지 여부
