## G05a — 차트 summary 수급 연결

- **우선순위:** P1 · **상태:** 완료 (2026-10-14, main 반영) · **선행:** [G01a](data.md#g01a) 구현·로컬 DB 회귀 통과, 원격 CI는 검증 대기 · **검증:** [QA02](qa.md#qa02)의 G05a 범위; 별도 QA 세션 판정은 사용량 제한으로 미완료, 메인 경계 검증으로 보완.
- **근거:** [chart loader:72·123](../../../src/invest_bot/dashboard/streamlit_state.py)는 날짜 없는 detail의 병합을 포기한다. 데이터 세션이 유효 summary를 함께 넣은 fixture에서 OHLCV만 남는 경로를 재현했다. [리포트 생성기:66](../../../src/invest_bot/jobs/generate_market_report.py)는 실제 summary 날짜·수급을 사용한다. 기존 [차트 fixture](../../../tests/test_dashboard_snapshot_frame_loader.py)는 detail에 날짜가 있는 형태다.
- **작업:** 실제 summary 관측일의 수급을 기존 snapshot으로 연결한다. summary 사용 자체가 오류라는 이전 추론은 철회됐으며 데이터 계약을 변경하지 않는다.
- **완료 조건:** summary만 유효한 fixture에서 날짜별 수급값을 표시한다. 원본이 없거나 날짜가 맞지 않으면 값을 만들지 않고 사유를 표시한다. snapshot 생성 후 추가 SELECT0회를 유지한다.
- **착수 정책 (2026-10-13):** 기존 유효 날짜·수급 상세 입력을 보존하며, 상세에서 관측일별 수급을 얻을 수 없으면 실제 날짜와 값이 있는 summary를 기존 snapshot에서 연결한다. 날짜 없는 상세 값을 가격 날짜에 복제하거나 날짜만 있는 summary로 다중 상세의 날짜를 추정하지 않는다. 누락·무효 날짜/값·차트 기간 불일치는 기존 상태 컴포넌트로 안내한다. 데이터 저장 계약·조회/생성 경계·다른 개선 항목은 변경하지 않는다.
- **반영 결과:** detail 전체 source를 우선하고 무효일 때 summary로 대체한다. source 사이의 누락 날짜·투자자 값은 섞지 않으며 숫자형 관측일·0·null을 구분한다. 가격 시각·시간대는 보존하고 실제 관측일로 연결하되, 같은 날 가격 행이 여러 개면 일별 수급을 복제하지 않는다. 가격 프레임의 잔여 수급 alias도 제거한다. 주·월봉의 모두 미관측인 수급은 null이다.
- **검증:** 격리본·원본 관련199 passed, 원본 기본832 passed / 2 deselected. 실제 가상 데이터 앱의 리포트·관심종목·데이터 보기, 누락·불일치, 1920×958·390×844를 확인했다. chart loader 추가 SELECT0회·검색/선택/탭 왕복 실행·전송0회다. 전체 리포트 rerun은 기존과 같은 SELECT3(snapshot2 + 즐겨찾기1)이며 전체 snapshot 이후0회라는 주장은 하지 않는다. [검증 기록](../../tasks/04_dashboard.md#차트-summary-수급-연결-2026-10-13).
- **남은 범위:** 운영 데이터·배포·원격 CI·별도 QA 세션 최종 판정은 미검증이다. 모바일 범례/제목 겹침은 G08d에 남긴다. 다음 기능 단위는 G05b다.

## 실행 기록

2026-10-14 기능별 커밋: 사용자 요청으로 G05a 코드·회귀5파일과 관련 문서9파일을 main에 반영했다. 다른 기능과 공유하는 문서는 G05a 부분만 선택했고 제외된 상세 보고서·산출물은 포함하지 않았다. 실제 커밋 후보만 격리해 관련199 passed, 기본832 passed / 2 deselected / 32 warnings와 문서 링크를 확인했다. 별도 QA 판정·원격 CI·운영 배포는 미검증이며 push·재시작은 수행하지 않았다.

2026-10-13 최종 결과: 담당 구현 종료 후 기존 QA 세션이 사용량 제한으로 중단됐다. 추가 크레딧·새 세션 없이 메인이 별도 경계10개를 작성해7 failed / 3 passed를 재현하고 시각·시간대 연결 오류와 가격 원본의 수급 alias 혼합을 보완했다. 격리본·원본 관련199개와 원본 기본832개를 통과했고 실제 앱에서 summary 패널·누락 사유·조회 전용 경계를 확인했다. 기능5파일의 원본/격리 검증본/화면 검증본 해시, 설정4개·기존 백업 보존을 확인했다. 임시 서버·탭은 정리했다. G05a 완료·커밋 전이며 QA02 전체와 원격 CI 상태는 유지한다. 별도 QA 세션의 독립 완료 판정을 받은 것으로 보고하지 않는다.

2026-10-13: 사용자 요청으로 G05a를 시작했다. G04 코드 `0f50fa4`·문서 `b9fd5da`가 main에 커밋됐고 원본 변경은 기존 백업 파일뿐인 것을 확인했다. 최신 추적 파일만 격리 복사해 기존 대시보드 세션에서 구현하고, 종료 후 기존 QA 세션의 독립 검증과 메인의 실제 브라우저 확인·원본 통합을 순차 진행한다. 실제 설정·운영 데이터는 격리본에 포함하지 않으며 커밋·push·운영 재시작은 수행하지 않는다. G01a·QA01 원격 CI와 G05b/G06 이후는 재개하지 않는다.

2026-10-13 담당 구현: 기존 대시보드 세션이 loader·chart·기능 회귀4파일을 완료했다. 수정 전30개 실패를 기록했고 최종 관련80 passed / 107 deselected다. snapshot 프레임 재사용 후 추가 SELECT0회를 확인했으나 필터된 담당 회귀가 전체 화면 검증을 뜻하지는 않는다. 세션 종료 후 같은4파일 해시의 격리본으로 기존 QA 세션을 실행했다. 원본 제품은 아직 변경하지 않았으며 메인의 수정 전 실제 가상 데이터 리포트 화면에서도 수급 누락을 확인했다. 해당 화면 전체 SELECT3(snapshot2 + 기존 즐겨찾기1), chart loader 추가0이다. 독립 QA·수정 후 실제 화면·원본 전체 테스트가 남아 있다.
