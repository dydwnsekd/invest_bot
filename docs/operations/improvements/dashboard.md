## G05a — 차트 summary 수급 연결

- **우선순위:** P1 · **상태:** 완료 (2026-10-14, main 반영) · **선행:** [G01a](data.md#g01a) 구현·로컬 DB 회귀 통과, 원격 CI는 검증 대기 · **검증:** [QA02](qa.md#qa02)의 G05a 범위; 별도 QA 세션 판정은 사용량 제한으로 미완료, 메인 경계 검증으로 보완.
- **근거:** [chart loader:72·123](../../../src/invest_bot/dashboard/streamlit_state.py)는 날짜 없는 detail의 병합을 포기한다. 데이터 세션이 유효 summary를 함께 넣은 fixture에서 OHLCV만 남는 경로를 재현했다. [리포트 생성기:66](../../../src/invest_bot/jobs/generate_market_report.py)는 실제 summary 날짜·수급을 사용한다. 기존 [차트 fixture](../../../tests/test_dashboard_snapshot_frame_loader.py)는 detail에 날짜가 있는 형태다.
- **작업:** 실제 summary 관측일의 수급을 기존 snapshot으로 연결한다. summary 사용 자체가 오류라는 이전 추론은 철회됐으며 데이터 계약을 변경하지 않는다.
- **완료 조건:** summary만 유효한 fixture에서 날짜별 수급값을 표시한다. 원본이 없거나 날짜가 맞지 않으면 값을 만들지 않고 사유를 표시한다. snapshot 생성 후 추가 SELECT0회를 유지한다.
- **착수 정책 (2026-10-13):** 기존 유효 날짜·수급 상세 입력을 보존하며, 상세에서 관측일별 수급을 얻을 수 없으면 실제 날짜와 값이 있는 summary를 기존 snapshot에서 연결한다. 날짜 없는 상세 값을 가격 날짜에 복제하거나 날짜만 있는 summary로 다중 상세의 날짜를 추정하지 않는다. 누락·무효 날짜/값·차트 기간 불일치는 기존 상태 컴포넌트로 안내한다. 데이터 저장 계약·조회/생성 경계·다른 개선 항목은 변경하지 않는다.
- **반영 결과:** detail 전체 source를 우선하고 무효일 때 summary로 대체한다. source 사이의 누락 날짜·투자자 값은 섞지 않으며 숫자형 관측일·0·null을 구분한다. 가격 시각·시간대는 보존하고 실제 관측일로 연결하되, 같은 날 가격 행이 여러 개면 일별 수급을 복제하지 않는다. 가격 프레임의 잔여 수급 alias도 제거한다. 주·월봉의 모두 미관측인 수급은 null이다.
- **검증:** 격리본·원본 관련199 passed, 원본 기본832 passed / 2 deselected. 실제 가상 데이터 앱의 리포트·관심종목·데이터 보기, 누락·불일치, 1920×958·390×844를 확인했다. chart loader 추가 SELECT0회·검색/선택/탭 왕복 실행·전송0회다. 전체 리포트 rerun은 기존과 같은 SELECT3(snapshot2 + 즐겨찾기1)이며 전체 snapshot 이후0회라는 주장은 하지 않는다. [검증 기록](../../tasks/04_dashboard.md#차트-summary-수급-연결-2026-10-13).
- **남은 범위:** 운영 데이터·배포·원격 CI·별도 QA 세션 최종 판정은 미검증이다. 모바일 범례/제목 겹침은 G08d에 남긴다. 다음 기능 단위는 G05b다.

## G05b — 원본·판단 기준일과 다음 행동

- **우선순위:** P1 · **상태:** 완료 (main 반영: `9867d48`, 검증일 2026-10-18) · **선행:** G05a. 생성된 판단의 정확성 완료 표시는 [G03·G04](quant.md) 검증 이후 · **검증:** QA02의 G05b 범위, 메인 검증·기존 대시보드 하위 에이전트 읽기 전용 리뷰.

- **작업:** 기존 상태 계산을 재사용해 홈·리포트·관심종목의 원본 날짜·판단 날짜·필요 단계를 통일한다. 판단 날짜를 최신 원본 날짜로 덮어쓰지 않는다.
- **완료 조건:** 원본10/02·분석 이전 날짜, 원본 누락, 날짜 불일치를 각각 구분한다. 원본 최신·분석 지연이면 분석 갱신을 안내한다. 검색·선택·탭 이동은 선택 상태만 복원하며 수집·분석·생성·전송 호출0회를 유지한다.
- **착수 (2026-10-18):** main `63bba25`의 추적 파일만 임시 작업 공간에 복사해 구현·회귀·화면 검증을 진행한다. 기존 대시보드 하위 에이전트를 읽기 전용 경계 확인에 재사용하며 전문 작업은 순차 진행한다. 원본 설정·운영 데이터·백업은 보존하고 commit·push는 수행하지 않는다.
- **반영 결과:** 원본 가격·수급과 분석 지표·전략 신호·판단 리포트 날짜를 분리한다. 원본 최신·분석 지연은 분석 갱신, 원본 누락·지연은 해당 원본 확인, 원본 또는 판단이 기준일보다 앞서면 불일치를 안내한다. 선택 리포트의 저장 날짜를 보존하고 홈은 종목별 상태를 집계한다. 탭 왕복으로 위젯이 정리돼도 선택 리포트를 복원하며 현재 선택값을 우선한다. 다음 행동 버튼은 화면 이동만 한다.
- **검증:** 신규25개를 포함해 관련220 passed, 최종 격리 후보 기본918 passed / 2 deselected / 32 warnings. 실제 renderer 3화면×4상태, 검색·선택·탭 왕복, 실제 임시 SQLite snapshot 이후 세 상태 소비자의 추가 SELECT0회와 실행·전송0회를 확인했다. 가상 데이터 실제 브라우저 1920×958·390×844에서 새 날짜·안내의 표시와 줄바꿈을 확인했다. 기존 하위 에이전트 리뷰에 차단 결함은 없었다. [계약·검증 기록](../../tasks/04_dashboard.md#원본판단-기준일과-다음-행동-2026-10-18).
- **남은 범위:** 운영 데이터·실제 API·배포·원격 CI·별도 QA 세션 종합 판정은 미검증이다. 기존 평일 기준일·날짜 컬럼 우선순위·파일 읽기 경로는 유지하며 휴장일·장중 판정은 확장하지 않았다. 후속 실행 안내는 G06a에서 보완했으며 G06b와 QA02 전체는 대기다.

## G06a — 생성·전송 범위 안내

- **작업:** 버튼 주변에 대상 종목·실행 단계·Discord 전송 설정 여부를 표시한다. 기존 실행·전송 정책은 보존한다.
- **완료 조건:** 클릭 전에 안내를 확인할 수 있다. 조회·선택만으로 실행0회, 클릭 mock에서는 기존 호출횟수와 부분 실패 표시를 보존한다. 실제 전송 성공을 설정만 보고 보장하지 않는다. 안내 수정 검증에는 실제 Discord 호출이 필요하지 않다.
- **착수 (2026-10-19):** main `9867d48` 기준 추적 파일을 격리해 안내와 실제 renderer·명시 클릭 경계를 검증한다. 기존 대시보드 하위 에이전트는 읽기 전용 테스트 경계 확인에 순차 재사용했다. 실제 설정·API·DB·Discord 호출과 commit·push는 수행하지 않는다.
- **반영 결과:** 실행 대상의 종목명·코드·총 개수와 기존 조회 기간을 표시한다. 5개 버튼 위에 처리 단계를 설명하고 전체 파이프라인은 수집 성공 종목만 후속 처리함을 안내한다. 기존 settings의 웹훅 값이 공백이면 미설정으로 표시하며 리포트 저장·전송 건너뛰기를 구분한다. 설정됨은 전송 시도를 뜻하며 성공 여부는 실행 결과에서 확인하도록 안내한다. 사전 안내에 웹훅 주소·토큰을 표시하거나 추가 조회를 넣지 않았다. 기존 실행 함수는 AST가 동일하다.
- **검증:** 신규20개를 포함한 관련169 passed, 최종 격리 후보 기본938 passed / 2 deselected / 32 warnings. 실제 renderer의 선택·기간·설정 변경은 작업0회, 5개 버튼 명시 클릭은 기존 호출 순서·대상·전송 정책을 유지한다. 빈 선택·수집 부분/전체 실패·Discord skipped/failed 경고를 확인했다. 가상 앱 실제 브라우저 1920×958·390×844에서 클릭 전 안내와 줄바꿈, 가상 클릭 후 미설정 경고를 확인했다. [검증 기록](../../tasks/04_dashboard.md#생성전송-범위-안내-2026-10-19).
- **남은 범위:** 운영 데이터·실제 API/DB·실제 Discord 전달·배포·원격 CI는 미검증이다. 기존 대시보드 하위 에이전트의 읽기 전용 리뷰에 차단 결함은 없었으며 별도 QA 세션 종합 판정과 구분한다. 다음 기능은 G06b이고 QA02 전체는 대기다.
