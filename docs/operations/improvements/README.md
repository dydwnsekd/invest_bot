## 이 문서를 읽는 방법

사용자가 다음 작업·우선순위·진행 상태를 물으면 이 색인과 해당 역할 문서를 먼저 확인한다. 전체 실행 순서는 여기서, 작업의 상태·근거·완료 조건·검증 기록은 역할 문서에서 관리한다. 기준 코드가 달라지면 현재 코드와 대조한 뒤 답한다. 계획을 구현 완료로 해석하지 않는다.

최초 개선 검토 기준은 main `1bd1dfa`이며 기존 다섯 세션의 10월 5일 검토를 통합했다. 2026-10-17 문서 대조 기준 HEAD는 main `efdc607`이다. G04는 코드 `0f50fa4`·문서 `b9fd5da`, G05a는 `1e23b95`로 반영됐다. 이후 보충 수집·비교 리포트·슬라이딩 혼합 연구·Git 제외 설정도 기능별로 반영됐으며 [현재 작업 요약](../../tasks/00_summary.md#현재-상태-2026-10-17)에 커밋과 검증 범위를 정리했다. 역할별 세션·파일 소유권·한 번에 전문 작업 하나의 원칙을 유지한다.

최근 반영된 별도 보충 수집 CLI가 일반 수집 G08a의 완료를 뜻하지 않으며, CSV 기반 혼합 전략 연구도 대시보드 조합 설정 저장·재로드 G08c의 완료를 뜻하지 않는다. 연구 기능 반영으로 아래 개선 순서나 QA 대기 상태를 바꾸지 않는다. 기본 suite893개는 10월17일 연구 커밋 후보의 기록이며 현재 배포·원격 CI 검증과 구분한다.

G01a·QA01은 `b29c346`으로 커밋됐고 로컬 DB 검증을 통과했으나 원격 CI 확인 전이라 검증 대기다. G02는 `7fb6435`로 반영됐으며 관련118개·기본508개와 모의 완료 조건을 통과했다. 실제 Docker 기동은 미검증이다. G03은 기존 퀀트→QA→보완→QA를 순차 재사용해 관련152개·기본635개를 통과했고 Docker 설정 제외 보완과 함께 `a22254a`로 main·origin/main에 반영됐다.

G04 검증 종료 당시에는 커밋 전 상태였고 이후 위 두 커밋으로 main에 반영됐다. 10월 13일 G05a도 관련199개·원본 기본832개·실제 가상 데이터 브라우저 검증을 마쳤고 10월 14일 기능 단위로 main에 커밋했다. ## 작업 상태와 갱신 규칙

상태는 **대기 → 진행 중 → 검증 대기 → 완료**로 기록한다. 실행이 불가능하면 **보류**로 표시하고 이유·재개 조건을 적는다. 완료는 해당 작업의 완료 조건과 새 검증 증거가 있을 때만 사용한다. 역할 문서의 요약표와 본문 상태를 함께 갱신한다.

작업을 진행한 세션은 해당 항목에 변경 요약, 검증 날짜·대상 HEAD 또는 작업 트리, 명령/환경, 결과, 미검증 범위를 남긴다. 검토 당시의 memory fixture·mock·AppTest·실제 브라우저·운영 읽기 전용 SQL을 구분한다. 과거 성공 수치를 새 변경의 검증으로 재사용하지 않는다.

우선순위·선행 관계·추천 순서가 달라지면 역할 문서와 이 색인을 함께 갱신한다. 통합 계획과 task 요약은 상세 조건을 중복 관리하지 않고 이 목록을 참조한다. 질문 자체는 구현 실행 요청이 아니며, 실행 요청은 해당 작업 범위에 맞춰 진행한다. 기존의 커밋 전 검토·순차 진행 원칙을 따른다.

commit·push는 [agent 가이드의 명시적 요청 규칙](../../../agent.md#커밋과-push)을 따른다. 구현·문서·검증이 끝났어도 일반적인 진행 요청만으로 로컬 commit이나 원격 push를 수행하지 않는다.
