### 시장 리포트 공통 기준일

- indicator, signal, investor 입력을 날짜순으로 정규화한다.
- 각 필수 source의 최신 유효일 중 가장 이른 날을 `reference_date`로 정한다.
- 각 source에서는 `reference_date` 이하의 최신 행만 선택한다. 해당 행이 없으면 `MarketReportDataError`로 생성 자체를 중단하므로 미래 데이터가 과거 리포트에 섞이지 않는다.
- indicator와 signal은 `date`, `trade_date`, `stck_bsop_date` 중 존재하는 날짜 컬럼이 필요하다.
- investor는 같은 날짜 컬럼을 우선하고, 상세 snapshot에 날짜가 없으면 일치하는 `investor_daily_summary`의 관측일을 사용한다. 요청일 기반 파일명은 관측일로 사용하지 않는다.
- indicator, signal, investor는 모두 필수다. 빈 frame, 유효 날짜 없음, 기준일 이하 행 없음은 허용하지 않는다. stock info는 기존처럼 선택 입력이다.
- 기존 `date` 필드는 공통 기준일을 계속 제공하며 기존 분석/전략/의견 필드는 유지한다.

추가된 source 계약은 다음과 같다.

| 필드 | 의미 |
| --- | --- |
| `reference_date` | 모든 필수 source가 미래 혼입 없이 함께 설명할 수 있는 공통 기준일 |
| `indicator_date`, `signal_date`, `investor_date` | 실제 선택된 source 행의 기준일 |
| `*_data_status` | source 날짜가 공통 기준일과 같으면 `aligned`, 더 과거면 `lagging` |
| `*_date_source` | `column:<column_name>` 또는 investor summary 연결 경로의 `summary:column:<column_name>` |

## 2026-09-15 investor 관측일 계약 보강

- `investor_daily` 파일명의 날짜는 collector 요청일이므로 실제 관측일로 사용하지 않는다.
- 날짜 컬럼이 있는 기존 detail 입력은 그대로 사용한다.
- 날짜 없는 detail은 같은 파일명의 `investor_daily_summary`를 읽는다. summary에 날짜별 수급값이 있으면 summary 행을 source로 우선 사용하고, 날짜만 있으면 단일 detail 행에만 최신 관측일을 연결한다. 날짜 없는 다중 detail 행에는 같은 날짜를 소급 할당하지 않는다.
- summary가 없거나 유효 관측일이 없으면 `MarketReportDataError`로 리포트 생성을 중단하고 investor 데이터 갱신을 안내한다.
- `run_market_report.py` 결과에 `investor_summary_file`을 추가했다.
- 일요일 요청 파일과 금요일 summary 관측일을 결합해 공통 기준일이 금요일로 유지되는 회귀 테스트를 추가했다.
- summary 최신일보다 indicator/signal 기준일이 과거일 때 동일 과거일의 summary 수급값을 선택하는 회귀를 추가했다.
- 날짜만 있는 summary와 날짜 없는 다중 detail은 정렬 근거가 없으므로 명시적으로 거부한다.
- summary에 수급 컬럼이 하나라도 있으면 실제 날짜별 source로 우선하며, 누락 수급값은 `unknown`으로 유지한다. detail이 비어도 날짜와 수급값이 있는 summary만으로 생성할 수 있다.
